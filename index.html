// PROJET 03 - FULL-STACK MARKETPLACE

Near-Job

URL: near-job.com Marché: Canada (FR/EN) Année: 2025-2026 Statut: Live en production

Plateforme marketplace full-stack de services de proximité ciblant le marché canadien (FR/EN). Maîtrise end-to-end : schéma de base de données → APIs JSON → UI interactive. Custom MVC sans framework, sécurité OWASP autonome, SEO scalable avec 10 000 landing pages programmatiques, workflow de vérification 4 niveaux, messagerie temps réel et conformité GDPR (hashing IP SHA-256).

Stack

PHP 8.1 (POO) Custom MVC + PSR-4 MySQL 8 (14 tables) 15 indexes stratégiques CSS3 (3 167 lignes) Vanilla JS ES6+ (946 lignes) Apache 2.4 + mod_rewrite Zero frameworks

Fonctionnalités clés

  • Recherche AJAX autocomplete - métier + ville avec tolérance synonymes, debounce.
  • Algorithme Haversine - calcul de distance géographique réelle (lat/lng).
  • 10 000 pages SEO programmatiques - /plombier/montreal-qc, /electricien/toronto-on, etc. (46 villes × 55 métiers).
  • Système de vérification 4 niveaux - Lvl 0 (aucune), Lvl 1 (identité), Lvl 2 (activité/Kbis), Lvl 3 (premium). Panel admin avec review/approval/rejection, documents versionnés (audit trail), expiration 12 mois.
  • Profils prestataires - galerie portfolio, zones d'intervention, langues, années d'expérience, KPI temps de réponse, compteurs de vues.
  • Messagerie - polling AJAX 5s, threading conversations, badges non-lus temps réel, notifications email.
  • Avis & trust - anti-spam (1 avis max par couple client-prestataire), file de modération, réponses prestataire, moyenne pondérée.
  • Sitemap dynamique - 5 000 profils + 10 000 combos métier×ville, robots.txt avec blocage GPTBot/CCBot.
  • Dashboard admin - compteurs temps réel, workflow de vérification, requêtes vendeurs.

Architecture

Custom MVC : Router, objet Request immuable (readonly PHP 8.1), PDO singleton lazy, injection directe des routes dans les contrôleurs. Pagination "peek" qui élimine la requête COUNT() supplémentaire. Database : 14 tables avec contraintes FK, indexes stratégiques sur Haversine (lat,lng), lookups slug O(1).

Sécurité (OWASP Top-10)

  • XSS - 161 appels htmlspecialchars + headers CSP.
  • SQLi - 100% prepared PDO statements, aucune interpolation de chaîne.
  • CSRF - tokens hex 64 caractères, comparaison timing-safe.
  • Auth - bcrypt cost=12, session regeneration, anti-énumération.
  • Rate limiting - 5 login/15min, 3 forgot/30min.
  • File upload - validation magic bytes (finfo).
  • Access control - requireAuth() + requireRole() sur toutes les routes protégées.
  • Headers - X-Frame-Options: DENY, X-Content-Type-Options: nosniff, HSTS, CSP, Permissions-Policy.

Maîtrise full-stack : conception DB → custom MVC → APIs JSON → UX interactive. Implémentation de sécurité autonome (OWASP) sans dépendre de la protection d'un framework. SEO à grande échelle : pages programmatiques, sitemaps dynamiques, schema.org. Product thinking : workflows de vérification, mécanismes de trust, fonctionnalités temps réel, conformité GDPR. // PROJET 05 - E-COMMERCE MARKETPLACE

KmerShop

URL: En développement - MVP complet Marché: Cameroun Année: Janvier 2026 Statut: Development (MVP ready to launch)

Marketplace e-commerce complète end-to-end pour le marché camerounais. Projet de 1ère année démontrant la capacité à architecturer une application complète, de la base de données à l'interface. Construit sans frameworks pour maîtriser les fondamentaux web : schéma relationnel, architecture MVC, sécurité (CSRF, XSS, SQLi). Workflow multi-vendeur : onboarding → validation admin → publication produit. RBAC 3 rôles (client/seller/admin).

Stack

PHP 8+ (PDO) MySQL 8 (utf8mb4) HTML5 CSS3 (1 808 lignes) Vanilla JS (203 lignes) Remixicon 4.1 Font Awesome 6.5 Inter + Playfair XAMPP Zero npm

Fonctionnalités clés

  • Authentification & Access Control - 3 rôles (Client, Seller, Admin), bcrypt, session_regenerate_id(true) au login, requireRole() server-side, soft delete (flag is_active).
  • Espace Client - catalogue avec recherche/filtres/pagination (12/page), détail produit (image, prix FCFA, stock, vendeur), panier persistant (DB), checkout livraison, simulation paiement Orange Money / MTN MoMo, numéro de commande auto KS-YYYYMMDD-XXXX.
  • Espace Vendeur - demande vendeur → validation admin, CRUD produits (création, édition, soft delete), upload images validé, workflow de publication (draft → pending → approved/rejected), dashboard avec statistiques.
  • Espace Admin - dashboard temps réel (clients, vendeurs, boutiques, produits, commandes), validation/rejet des demandes vendeur avec notes obligatoires, workflow de modération produit, suspension boutiques, bulk actions utilisateurs.
  • UI/UX - responsive mobile-first sans framework CSS, hamburger menu avec overlay, flash messages auto-dismiss 5s, modale de confirmation custom (remplace le confirm() natif), 404 personnalisée.

Architecture base de données (10 tables)

  • users - comptes utilisateurs (rôles client/seller/admin), is_active.
  • profiles - profils vendeurs, info boutique.
  • category - 7 catégories fixes (Électronique, Mode, Maison, Alimentation, etc.).
  • seller_request - workflow d'onboarding (pending/approved/rejected).
  • shop / shop_member - boutiques vendeurs et relation 1-to-1 vendeur ↔ boutique.
  • product - produits avec workflow de publication, soft delete.
  • cart_item - paniers persistants par utilisateur.
  • order / order_item - commandes avec status & livraison, lignes denormalisées (snapshot prix/nom).
  • payment - enregistrements de paiement (simulés).

Sécurité

  • SQLi - 100% prepared PDO statements.
  • XSS - htmlspecialchars() sur toutes les sorties (helper e()).
  • CSRF - tokens sur tous les formulaires.
  • Password - password_hash() (bcrypt).
  • Session - session_regenerate_id(true) au login.
  • Access control - requireRole() server-side sur les pages protégées.
  • File upload - validation par magic bytes (pas seulement Content-Type).
  • .htaccess - protection des dossiers config/, includes/, uploads/.
